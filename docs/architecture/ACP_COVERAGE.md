# ACP client coverage

What Spark Outpost supports as an ACP **client**, tracked against the ACP v1 JSON Schema in [`docs/reference/acp/schema.json`](../reference/acp/schema.json). How the runs work is in [ACP_AGENTS.md](ACP_AGENTS.md).

- **Source of truth.** Statuses live in [`acp-coverage.json`](acp-coverage.json), keyed by surface ID. The Summary and Surfaces sections below are generated from it.
- **Check.** `pnpm acp:coverage` lists every protocol surface in the schema and fails when one has no entry, when a `partial` entry has no note, or when this file is out of date. A new schema version therefore shows up as a failure.
- **Update.** Edit `acp-coverage.json`, then run `pnpm acp:coverage render`. Edit the text outside the generated block by hand.
- **Status.**
  - **supported:** works today and meets the spec.
  - **partial:** works, but the note says what is missing.
  - **missing:** not built.
  - **not_applicable:** we don't advertise or need it, so the spec asks nothing of us.
- **Where** paths are relative to `apps/server/src/agents/acp/` unless they start elsewhere.
- **Unstable (outside the stable v1 schema)** lists entries the code handles although the stable schema doesn't define them. The check accepts them only if the unstable schema bundled with `@agentclientprotocol/sdk` (`schema/schema.json`) defines them, so keep the SDK pinned while they exist. Spec conformance, extensions and adapter-specific behaviour are audited in [ACP_COMPLIANCE.md](ACP_COMPLIANCE.md).

## MUST rules at a glance

| Rule (spec wording, short)                                                          | Us                                                                                                                                              |
| ----------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Clients "MUST initialize the connection" before a session                           | Met in `acp-provider.ts` and `probe.ts`                                                                                                         |
| `initialize` "MUST include the latest protocol version"                             | Met. We send `PROTOCOL_VERSION` (1)                                                                                                             |
| Treat omitted capabilities "as UNSUPPORTED"                                         | Met. Capabilities are checked with `=== true`, and no optional method is called                                                                 |
| Clients "MUST restrict types of content" to prompt capabilities                     | Met. Images and embedded resources are gated by `promptCapabilities`. Audio is never sent                                                       |

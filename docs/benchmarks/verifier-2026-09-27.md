# Verifier measurement · 2026-09-27

The round-10 verifier said "would pass" on all 42 lean runs it saw, and none of them failed, so its recall was unknown. This measures the new three-way diff verdict (routing plan section 5) on a set built to fail, before letting it act.

Data: [verifier-2026-09-27.json](verifier-2026-09-27.json). Code: `scripts/verifier/` (`npx tsx scripts/verifier/measure.ts [--critic] out.json`).

## The set

12 small tasks on the bench fixture (`scripts/bench/fixture/base`, the ledger-lite repo). Each task has two hand-written diffs, applied deterministically with no model:

- **wrong**: a plausible Builder diff that passes the project's visible check (`node --test "test/**/*.test.ts"`) but misses one stated requirement;
- **correct**: a diff that does everything asked.

A hidden test per task (in the task file, never shown to Jev) confirms the label: every one of the 24 diffs passes the visible check, the 12 wrong diffs fail their hidden test, and the 12 correct ones pass it. The runner refuses to score a case whose label does not hold.

| Task | What the wrong diff misses |
| --- | --- |
| percent-zero | `percentOf` returns 0 when total is 0 |
| parentheses-negative | `(12.50)` parses as negative (it strips the parentheses only) |
| thousands-groups | every group of thousands gets a comma (only the first does) |
| sum-skips-blanks | blank strings are skipped |
| apostrophe-names | `o'neil` → `O'Neil` (hyphens only) |
| due-on-receipt | `'Due on receipt'` at 0 days (only the default of 30) |
| tax-after-discount | tax on the discounted amount (it taxes the subtotal) |
| average-skips-transfers | divides by the entries kept (divides by all entries) |
| categories-by-total | ties in alphabetical order |
| guest-greeting | a name of only spaces |
| share-in-report | one decimal in the percentage (`25%`, test changed to match) |
| case-insensitive-ledger | `totalFor` ignores case (only `categories` does) |

Jev received exactly what the harness sends: the task, the plan (none), the check line (`passed`), the full diff, one Choice `verdict` (supported, unsupported, declined, each with `what` and `not_for`), and one `unmet_N` Noul per requirement line. The Critic received the harness's own `criticPrompt` (request, plan, files, diff, check results) on real Claude Sonnet (`claude-sonnet-5`, no tools). The question wording was written once and not tuned on this set.

## Results

Positive = the wrong diff. Two Jev runs over the same 24 cases gave the same decisions (confidences moved by at most 0.1); the table is the second run, which also ran the Critic.

| Signal | Flagged | True positives | Precision | Recall |
| --- | --- | --- | --- | --- |
| **Jev "unsupported", accepted (confidence ≥ 0.8)** | 11 | 10/12 | **91%** | **83%** |
| Jev "unsupported", top choice at any confidence | 14 | 11/12 | 79% | 92% |
| Jev worst requirement Noul ≥ 0.8 | 10 | 10/12 | 100% | 83% |
| Jev worst requirement Noul ≥ 0.5 | 11 | 10/12 | 91% | 83% |
| Critic (Sonnet) "Verdict: concerns" | 14 | 12/12 | 86% | 100% |

- **Declined:** never the top choice (0 of 48 answers); its probability was 0.00–0.01 everywhere. The set has no refused or half-finished work, so how well "declined" fires when it should is **not measured**.
- **Accepted at 0.8:** 20 of 24 answers. Not verified (below 0.8): two correct diffs (percent-zero 0.36, guest-greeting 0.71), one correct diff leaning unsupported (parentheses-negative 0.77) and one wrong diff (average-skips-transfers 0.33).
- **Misses:** tax-after-discount wrong was accepted as supported (0.88): the tax is applied to the pre-discount subtotal, a one-expression difference. average-skips-transfers wrong was not verified (0.33): the filter is right, the divisor is not.
- **False alarm:** thousands-groups correct was accepted as unsupported (0.84, run 1: 0.82); its test covers only the one-comma case the request mentions first.
- **The Critic** caught all 12, including both Jev misses, but its two false alarms (parentheses-negative and thousands-groups correct) were about test coverage, not behaviour.
- **Cost:** Jev $0.0013 per 24 calls (1,080–1,390 input tokens each, about $0.00005 per call). Critic $0.29 per 24 calls (about $0.012 per call, 230 times Jev). Total spend for the measurement, both runs: about $0.30.

## Decision

The bar was unsupported recall ≥ 0.7 with precision ≥ 0.8. The accepted Jev verdict measured **recall 0.83, precision 0.91**, so **the cascade acts**:

- after the Builder and its checks and fix turns finish green, an accepted **unsupported** reruns the Builder once, one tier up (`escalate`), in the same task session and worktree, with the requirement lines Jev judged unmet as the follow-up;
- an accepted **declined** raises a "Jev could not verify the change" card (Finish as it is, Retry with the next tier, Stop; auto-continue picks Finish);
- **supported** or anything below 0.8 finishes as before;
- without Jev (no key, unavailable, or diffs turned off) nothing changes: checks and 2 fix turns only.

## Limits

- 24 cases, one fixture, one author for both the diffs and the question. Treat the numbers as a first check, not a tuned threshold. Precision per verdict and the 0.8 line should be refitted on real runs (`pnpm jev:thresholds` now reads the probability of "unsupported" from `cascade-1` rows).
- The wrong diffs each miss exactly one stated requirement in a small diff. Large diffs, vague requests and refused work are not covered.
- The Critic is stronger on this set (recall 1.0) but costs about 230 times more per call and still runs only for destructive work, review requests and large diffs. Whether large diffs should get both is still open (routing plan, open questions).

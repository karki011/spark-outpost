# Developer's day · 2026-09-28 (live)

The first live run of the developer's-day benchmark ([plan](dev-day-PLAN.md), code in
`scripts/e2e-live/dev-day/`): fourteen sessions of one working day, played in order against the
harness (the app driven through its HTTP API, as the web UI drives it), direct Claude (one Sonnet
agent, medium, no orchestrator) and direct Codex (`codex exec`, gpt-6-sol, medium). Branch
`bench/dev-day-live` on top of `4833f43` (permission rename, Full auto → draft PR, Ship, repo agent
config, Critic fix loop, Builder floor, plan capture).

Data: [dev-day-2026-09-28.json](dev-day-2026-09-28.json) (the scored run, the raw scores, the s13
rerun and the issues below; the s14 replies about the read-only work repo are left out).

**Spend: $6.90 of the $25 cap** ($6.59 for the main run, $0.31 for the s13 rerun). Nothing hit a
session cap, no rate limits, no session was blocked. Codex cost is estimated from tokens.

**n = 1 per cell.** Every pass/fail below is one run. A single flip changes an arm's pass rate by
7 points, so the ranking between the harness and direct Claude (one session apart) is weak; the
per-session harness findings are strong where they come with a log or code line that explains
them, and are marked below.

## Harness bugs and gaps, by priority

1. **Review requests go to a read-only Scout that cannot see the diff, and no Critic runs (s07,
   the harness's only failure). Strong.** Run `01a0e72e-4da1-74d0-a261-42338ca095f8`: crew
   `scout sonnet·medium`, no Critic. The Scout found the `median()` bug in the new, untracked file
   but missed the `plural()` bug in the modified file, and said why: "I can't diff against HEAD
   directly with the tools available here, but nothing in the current file content references
   `median`…". Direct Claude and Codex both named both bugs. Suggested fix: for
   review intent, put `git diff HEAD` plus untracked files into the Scout's (or Critic's) context,
   or allow read-only `git diff`/`git status` in Ask-mode tool policy; and route "review my
   changes" to the Critic, as the lean round already flagged (harness-e2e-lean-2026-09-27).
2. **Full auto: the Builder pushes and tries to open a PR itself, and says it can't, while the
   harness opens it (s12). Strong.** Run `01a0e739-d735-727c-b26f-43471cdf6b77`. The Builder's
   text: "This is a local file-based remote, not GitHub, so `gh pr create` won't work here. Pushed
   to `spark/01a0e739/bolt`. I can't ship a draft PR here…", followed by the harness's "Opened draft
   PR #1…". The fake remote ends with two branches: the Ship branch
   `spark/add-get-projects-id-expenses-the-01a0e739` and the Builder's
   `spark/01a0e739/bolt`, which also carries the internal snapshot commit
   `Spark Outpost: parallel base 01a0e739-… solo`. Screenshot: `main/dev-day-s12-harness.png`.
   Suggested fix: in Full auto the Builder prompt should say shipping is the harness's job (don't
   push, don't open PRs), and the Full auto policy should hold `git push` / `gh pr` from members for
   a card (or deny them) instead of auto-allowing them; strip the parallel-base commit from any
   branch that can leave the machine.
3. **The "complex → top tier" rule sends one-line fixes to Opus, overriding Jev (s05, s06).
   Strong.** Run `01a0e72a-e289-77e2-8e7c-80653472192c` (the typo): Jev said `tier: small`,
   `intent: bug_fix`, confidence 1; the route decision was "Why Opus 5.5: rule complex → top tier
   (matches in 4 packages) · Jev would have used Sonnet 5". The four packages come from the scan's
   loose matches on `Analytics`/`Spend*` symbols across web, contracts, server and root, not from
   the change. The typo cost $0.127 on the harness against $0.031 direct. Suggested fix: count
   packages from the ranked likely files above a probability cut (or from named paths), not every
   symbol match; and don't let this rule override a confident small-tier Jev call on a bug fix.
4. **"continue" after Stop starts a fresh Builder session (s13 rerun). Strong, with code.**
   Runs `01a0e73f-5b16-7640-bec7-f14ee2963ec2` (stopped at 9.4 s) → `01a0e73f-8004-7495-a009-194ff64bfbaa`
   ("started over"). `decideResume` in `apps/server/src/workflow/session-decision.ts` returns
   `fresh(RESUME_REASONS.unfinished)` when `lastReplyHash === null`, which is exactly the state a
   stopped turn leaves. The work was not duplicated this time (3/3 hidden tests, including
   "defined once"): the fresh Builder rebuilt the export rather than adding a second one. Suggested fix: resume an unfinished
   session when the new message is a continuation ("continue", "go on", or Jev's continuation
   intent) and the settings hash matches; keep the fresh start for everything else.
5. **Plan-only requests aren't recognised: an answer-or-build card instead of a plan card (s03).
   Strong.** Run `01a0e720-2217-75e0-93d3-c66e524252ff`, prompt ending "Plan only for now: don't
   change any files". Intake: Jev `intent: feature`, `question: 0.69`, gate `decision: ask`,
   so the developer got "Answer, or change the code? · Not sure whether you want an answer or a
   change.", then a Scout plan with no plan card; the bench saved it by hand. Two interventions for
   what direct Claude did with none. Suggested fix: a rule for explicit plan-only phrasing ("plan
   only", "don't change any files", "just a plan") that routes to the planner and shows the plan
   card; don't ask answer-or-build when the user already said which.
6. **No Critic on the plan build or the three-layer story (s04, s11). Medium.** s04 (run
   `01a0e723-60cd-7730-9310-d3a25a88182b`, 3 files, +103) and s11 (7 files, +98 −9, DB + API + UI)
   ran without a Critic; Jev's review score was 0.03 on s04. Both passed, so this cost nothing
   today, which is why it is medium; but the plan's harness contract says the Critic runs on
   these, and the Critic fix loop (≤3 rounds) was never exercised live. Suggested fix: run the
   Critic when an agreed plan is loaded, or when the diff spans more than one layer / package.
7. **No card before the Builder on the risky migration at Ask before edits (s10). Medium.** Top
   tier and a worktree were used and the Critic ran, but the first card was the keep card after the
   edits. The plan expects a plan card before a destructive schema change. Suggested fix: at Ask
   before edits, a migration or schema rename (`destructive` / risky intent) should show the plan
   card before the Builder.
8. **Every build at Ask before edits costs a "Keep these changes?" card. Low (by design, but
   priced).** Six of the harness's eight interventions. With Ask before edits the developer already
   approved every edit one by one (3–7 clicks per build); asking again to keep them is the part a
   developer would notice. Suggested fix: skip the keep card when every edit was approved by hand
   and the checks passed.
9. **The clarify card for "make it faster" offers the wrong choices (s08). Low.** It passed (the
   harness asked in 1.1 s, $0.0001), but the offered choices were "Restructure the code without
   changing what it does" and "Add new behaviour or features": nothing about performance. Suggested
   fix: let Jev phrase the choices for vague performance requests (what is slow: startup, a page, a
   query).

Not found: no harness errors, crashes, stuck runs or budget stops in 17 harness runs; plan capture
put the agreed plan in the s04 Builder prompt; the Builder floor never let a Builder run on Haiku
(it overshot instead, issue 3).

## Bench fixes made in this run

Committed on `bench/dev-day-live`:

- **Ship on the app's own GitHub fake.** `github-stub.ts` now wraps
  `apps/server/test/fake-github.ts` (same API surface as the server tests) and records any request
  that carries something other than the bench's fake token.
- **The real GitHub token can't be used.** The harness stack runs on the memory secret store in the
  live run too, seeded with the keychain's connection keys (Jev, Z.ai; read-only) and the fake
  GitHub token, so Ship never reads the keychain's `github:token`. `MEMORY_SECRETS` now accepts
  `github` (`apps/server/src/config.ts`, `setup/secrets.ts`); without it the worker had no way to get
  a GitHub token from the memory store, in the dry run either. The bench connects the fake GitHub
  with `PUT /api/github/token` for host `github.e2e.localhost`; `GITHUB_API_URL` points at the stub;
  `GH_CONFIG_DIR` is an empty directory (the runner refuses to start if it isn't);
  `GH_TOKEN`/`GITHUB_TOKEN`/`GH_ENTERPRISE_TOKEN`/`GITHUB_ENTERPRISE_TOKEN` are dropped. Proof
  recorded in the run's setup: GitHub connection "active token; gh CLI login none"; `gh auth status`
  under the stack's env "You are not logged into any GitHub hosts"; the stub saw 3 requests, all
  with the fake token ("foreign credentials: none"); every other `https://` remote in the workbench
  is rewritten to a dead path.
- **Balanced user for the current checkpoints** (`scripts/e2e-live/balanced.ts`): the
  "Answer, or change the code?" card follows the session's intent (it used to fall through to an
  option the card doesn't offer), `stuck` → Stop and report, `verify` → Finish as it is, and the
  keep card's "fix the findings" is taken when the Critic offers it.
- **Scoring**: an answered clarify card after which the run replied in full is an intervention, not
  the turn's action (it failed the harness's s03 plan); a markdown options table counts as options
  (it failed Codex's s02, a three-row table of options with trade-offs).
  `rescore-day.ts` re-scores a saved run; the tables above are the re-scored run.
- **s13**: the live Stop is now 8 s after the Builder starts (was 40 s, after both Claude arms had
  already finished).
- `levels.ts` documents the four choices after migration 0049; the stored values were already
  right (Ask = `ask`; Ask before edits / Auto-edit / Full auto = `do` + `balanced` / `hands-off` /
  `full-auto`). `BENCH_LEVEL` stays `full-auto` for the direct arms: they run `executeChildRun`
  without the orchestrator, so no worktree and no Ship.
- Full auto needed no click: it shipped on its own, so s12's prompt is unchanged and no click was
  added.

Checked: `--selftest` 14/14 OK; the dry run (`AGENT_RUNTIME=fake`) ran every session on every arm
and opened a draft PR on the stub in s12.

Known bench gap, not fixed: the spark copy excludes `scripts/e2e-live/dev-day/` but keeps
`scripts/e2e-live/run.ts`, which imports it, so `pnpm check` fails in the copy (Codex noticed it in
s04 and s08). The analytics checks the sessions use are unaffected.

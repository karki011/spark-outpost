# Upstream contributions to codex-acp

> **Drafts only.** Nothing here has been filed, commented or pushed. Review the drafts, then submit them from your own GitHub account. Research done September 27, 2026 using public, read-only access (no sign-in, no forks, no comments).

Spark Outpost patches `@agentclientprotocol/codex-acp` 1.13.1 ([PATCHES.md](../../architecture/PATCHES.md)). Part 1 (a real read-only sandbox) is already upstream through #480. This folder prepares the other three parts:

1. an "ask before every action" mode (`untrusted` approval policy, `workspaceWrite` sandbox, no network);
2. Codex's `decline` option, ahead of `cancel`, on command and file-change approvals, so that a denial doesn't end the turn;
3. `PromptResponse.usage` summed over the whole turn instead of only the last model request.

## The repository

- **Repo:** [agentclientprotocol/codex-acp](https://github.com/agentclientprotocol/codex-acp), TypeScript, Apache-2.0 (copyright JetBrains), published as `@agentclientprotocol/codex-acp`. Most maintainers are at JetBrains (nikita-ashihmin, Andrey Bragin, AlexandrSuhinin), plus Ben Brandt from the ACP side. PRs from outside contributors get merged (for example #480 by valentingoebel).
- **State checked:** `main` at `bf37821`. It contains everything in `v1.13.2-preview.5` plus nothing relevant after it. The previews since 1.13.1 contain #536, #480, #549 (codex 0.157.0), #550, #517 and #551. None of them touches topics 1 to 3. Release PR [#543](https://github.com/agentclientprotocol/codex-acp/pull/543) (1.14.0) is open.
- **Contribution rules.** There's no CONTRIBUTING file, no issue or PR template, and no CLA or DCO requirement: no bot, and only dependabot commits carry sign-offs. The rules live in `AGENTS.md` and CI:
  - The **PR title must be a conventional commit** (`feat`, `fix`, `perf`, `revert`, `docs`, `style`, `chore`, `refactor`, `test`, `build`, `ci`). `conventional-prs.yml` enforces it. The title is the squash-commit subject and drives release-please: `feat:` bumps the minor version, `fix:` the patch.
  - Tests go in `src/__tests__/` (Vitest). Maintainers prefer event-driven tests and `toMatchFileSnapshot()` snapshots under `src/__tests__/CodexACPAgent/data/`. E2E tests with a real Codex run through `npm run test:e2e` (`RUN_E2E_TESTS=true`, `src/__tests__/CodexACPAgent/e2e/`).
  - CI runs `npm ci`, `npm run typecheck`, `npm test` and `npm run bundle:all` (the last needs bun).
  - Style: four-space indent, double quotes. New env or config knobs are documented in `readme-dev.md`, and mode ids are listed in both `README.md` and `readme-dev.md`. In discriminated-union `switch`es, every variant gets an explicit `case`.
  - Existing issues and PRs are free-form, usually with Summary, Why and Testing/Validation sections. The drafts follow that.

Before you submit:

- Replace Spark Outpost internals (the patch file, `decide()`, the "gate") with neutral wording. The drafts already do this, apart from naming Spark Outpost as the client once.
- The probe numbers come from [CODEX_DO.md](../../architecture/CODEX_DO.md), run on September 26, 2026 against codex-acp 1.13.1 and `@openai/codex` 0.156.1. Upstream is now on 0.157.0. For the ask-always PR, rerun the `ls`, `cat .env`, `apply_patch` and denied `echo` rows against a local build of the PR branch, and put the result in the PR's Testing section.
- Mode id: the drafts propose `ask-always` ("Ask every time") instead of our `ask-every-action`, to match upstream's short ids. The mode keeps `workspace-write`'s sandbox, including a writable `/tmp`, for consistency with upstream. Our patch uses `excludeSlashTmp: true`. If upstream ships the drafted mode, set `CODEX_DO_MODE` to the new id and update the guard test in `agents.test.ts`. `/tmp` then becomes writable, but only for commands and edits that were already approved.
